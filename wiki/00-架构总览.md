# 00 · 架构总览 (全局分析)

## 1. 双输入流 + 六管线拓扑

MMPV 有**两条输入流**与**六条管线**（EVE 不再是独立管线，作为模块挂在 ①③ 内）:

```
输入流 A (reads 主链)                          输入流 B (宿主基因组/转录组)
① public_metadata_pipeline  ──┬── (hostdb 前) eve-mask
        │                     └── (hostdb 后) eve_genome → EVE 报告
        ▼
② data_preprocessing_pipeline ─── 00b_HostDepleted
        │
        ▼
③ virome_discovery_pipeline ──HQ vOTU──┬──→ ④ virome_analysis_pipeline
   (15 阶段; 09b 含 KEEP 前 EVE 判别)    │            │ 全长基因组
   │                                    │            ▼
   │                                    │      ⑤ virome_phylo_pipeline
   └── 09b eve_discriminate → EVE_like 否决 KEEP
        │
        ▼
⑦ virome_submission_pipeline → .sqn (GenBank/CNCB)
```

- **主链**: ①→②→③→(④→⑤) + ⑦ 收尾; ③ 的 `08_Rescue` 产物是全平台枢纽。
- **EVE 集成模块 (2026-10-25 重构, 不再单独成管线)**: 拆成两段 ——
  ① 基因组侧 `public_metadata_pipeline/eve_genome/` (hostdb **前**可选掩码; hostdb **后**
  `eve` 阶段扫描 + 元件库 + HTML, 并入 `Pipeline_Summary_Report.html` 的 S7);
  ③ 转录组侧 `virome_discovery_pipeline/eve_discriminate/` (09b CDD 验证后、五层证据整合
  **前**跑 16 科 ML/可选 Δbit, `EVE_like` 通过 `--eve-calls` 把 KEEP 降为 REVIEW,
  并入 `pipeline_report.html` 的 09b 卡片)。旧的 `endogenous_virus_pipeline/` +
  `eve_distinguish/` 已归档至 `archive/20261011_endogenous_virus_pipeline/`, 仅供历史复现。
- **⑧ 宿主表达支线 (已归档 2026-10-11, 方法不成熟; 2026-10-02 并入)**:
  `archive/20261011_host_expression_pipeline/` (原 `host_expression_pipeline/`)
  抽取自 goji-virome 差异表达分析的核心链路 —— 宿主 salmon 定量 → 定量 QC →
  病毒标签 (④ 检出表 → 阳性/阴性 + 连续载量) → **TEA-GCN 差异共表达 (05_Coexp,
  主分析: 阳/阴双网络 → ΔzScore, 带样本量/失衡闸门)** → DESeq2 (06_DE, 交叉参考,
  可选组织分层) → 载量×全基因组扫描 (07_LoadScan, 剂量验证, 自动组织内) → HTML
  报告。TEA-GCN 引擎 vendor 于 `teagcn/` (上游 MIT, 含已验证的 5× 提速补丁)。coexp 链含 KingdomStress (bioRxiv 10.64898/2026.04.17.719161) 方法移植: 网络 z 分布 QC 闸门 (Fig S8, Δz 守门员) + DEG 限定 Louvain 模块检测 (Fig 5, z≥1.7 ∩ DEG, 06_DE 后自动补跑) + 跨宿主模块保守性脚本 (OC≥0.5 & 共享 OG≥10 + 置换零模型, 独立脚本)。
  输入取 ② clean reads / ① 宿主参考与 Core14 / ④ 检出表 (B8), 输出落
  `08_HostExpression/`; **不在主链, 不跑无影响**。详见模块 README 与
  `ARCHIVED_20261011.md` (归档原因与恢复方法)。
- **GUI**: 已移交外部本地平台「植物病毒分析平台」(2026-10); ⑦ 管线内仍有独立 submission_gui.py。

## 2. 上下游边界契约 (B1–B8, 逐边核实过代码)

| # | 边界 | 交接产物 | 生产者 → 消费者参数 |
|---|---|---|---|

| B2 | ②→③ | `00b_HostDepletion/` (+`assembly_ready.list`) | `host_depletion.py` → `virome_pipeline.py --input_reads` |

| B4 | ④→⑤ | `06_Extraction/<病毒>/<样本>.full.fasta` | `extract_full_fasta.py` → `phylo_pipeline.py --extract_dir` |
| B5 | ①→⑤ | `Global_Unified_Metadata_Core14.csv` | `gsa_sra.info.py` → `phylo_pipeline.py --metadata` (原生直读) |
| B6 | ① hostdb→eve_genome | `all.genome.uniq.fasta` (宿主基因组) | `download_host_genome.py` → `public_data_pipeline.py --stage eve --eve-scan`（或 `build_host_pipeline.py --stage all --eve-scan`） |

(`--from-discovery <③根>` 即可, 兼容 legacy 三代目录名), 并登记
`90_Handoff/handoff_manifest.tsv` 交接台账。

## 3. 双目录布局 (v3.1)

| | standard (默认, 管线独立根) | legacy (存量项目回退) |
|---|---|---|
| 定义 | `01_PublicData` `02_Preprocessing` `03_Discovery` `04_Analysis` `05_Phylo` + `90_Handoff`（EVE 产物在 `host_reference/eve/` 与 `09b.../eve/`） | v3.0 现行名 (`00a_CleanData`/`02a_Identification`/`09a_Virome_Analysis`…) |
| 根内编号 | 各管线独立从 01 编号 (⑤ per-virus: 01_data…08_report) | 字母后缀体系 |
| 编排器根语义 | 每个 `--output_dir` 指向本管线自己的根 | ②③ 共享一个输出根 |
| 兼容性 | 冻结测试保护, 新项目直接开跑 | 需显式 `--io-layout legacy` (或 env); 既有 checkpoint 零改动 |

- 解析优先级: `--io-layout` > 环境变量 `MMPV_IO_LAYOUT` > standard (默认); 编排器入口
  `normalize_layout_env()` 写回环境, 子进程自动继承。
- 唯一注册表: `mmpv_common/io_layout.py` (35 逻辑键 × 2 布局); 改名 = 改一张表 +
  过 `mmpv_common/tests/test_io_layout.py` 冻结测试。
- 边界产物定位器 `locate_centroids()/locate_taxonomy()` 双布局通吃; 桥脚本
  `discovery2analysis.py --from-discovery` 无需开关。
- 完整规范: [doc/IO_LAYOUT_DESIGN.md](https://github.com/zhangwenda0518/MMPV-RNA/blob/main/doc/IO_LAYOUT_DESIGN.md)。

## 4. 横切机制 (全局)

| 机制 | 实现 |
|---|---|
| 断点续传 | 全编排器 `--resume/--force`; `.ok` 标记 + 产物核验双条件; ⑤ 用 `.checkpoints/` + 输入指纹; EVE 随 ①/③ 的阶段 checkpoint |
| 配置 | `pipeline_config.yaml` profile 体系 (default 锚点, plant/downstream 继承); 路径 `${ENV:-default}`; 优先级 CLI > profile > 代码默认 |
| 环境变量 | `MMPV_DB_ROOT` 一变量迁移全部库; 派生 `MMPV_VIRUS_DB`/`MMPV_HOST_DB`/`MMPV_EVE_*`/工具路径 |
| 布局传播 | `MMPV_IO_LAYOUT` 环境变量; 编排器入口 normalize, 子进程继承 |
| 防挂死 | `process_guard.py` (③④ 共用); `eve_genome/eve_screen.py --cmd-timeout` |
| 宿主控制 | ② Kraken2 `keep_taxids:10239` 病毒 reads 救回; ③ rescue 前宿主预过滤省 70%+ 计算 |
| 元数据主干 | `Global_Unified_Metadata_Core14.csv` 14 列标准表 (① 产出, ④⑤ 消费) |
| 部署 | `pixi.toml` 100 包; `database/setup/mmpv_db.py` 管理 50 项数据库 (必需 24 / 可选 26) |
| 版本台账 | `SOFTWARE_VERSIONS.txt`; 文档权威体系见各管线 doc.md |
