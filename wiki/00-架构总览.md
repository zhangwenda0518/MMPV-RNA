# 00 · 架构总览 (全局分析)

## 1. 双输入流 + 七管线拓扑

MMPV 有**两条输入流**与**七条管线**:

```
输入流 A (reads 主链)                        输入流 B (宿主基因组, 独立)
① public_metadata_pipeline                   ⑥ endogenous_virus_pipeline (EVE)
        │                                            ▲
        ▼                                            │ 输入=宿主基因组FASTA
② data_preprocessing_pipeline ─── 00b_HostDepleted ─────┘ (基因组另有来源)
        │
        ▼
③ virome_discovery_pipeline ──HQ vOTU──┬──→ ④ virome_analysis_pipeline
   (15 阶段)                           │            │ 全长基因组 06_Extraction
   08_Rescue 终审判决表                 │            ▼
   │                                   │      ⑤ virome_phylo_pipeline
   └── 候选 contig ──→ ⑥ 判别器 ──→ dna_vs_eve_filter.tsv
        │
        ▼
⑦ virome_submission_pipeline → .sqn (GenBank/CNCB)
```

- **主链**: ①→②→③→(④→⑤) + ⑦ 收尾; ③ 的 `08_Rescue` 产物是全平台枢纽。
- **EVE 支线**: 输入是宿主参考基因组 (非 reads), 与主链相互独立; ⑥ 的判别器
  (`eve_distinguish/`) 在 ③ 之后运行, 对候选做 "真 DNA 病毒 vs 退化 EVE" 判定。
- **GUI**: `metadata_gui` (复用 ① 的检索代码) 与 `submission_gui` (⑦ 的交互前端)。

## 2. 上下游边界契约 (B1–B7, 逐边核实过代码)

| # | 边界 | 交接产物 | 生产者 → 消费者参数 |
|---|---|---|---|
| B1 | ①→② | raw FASTQ + `sample_handoff.csv` + Core14 元数据 + 宿主四索引 | `generate_report.py` → `data_preprocessing.py --input_reads --host_db` |
| B2 | ②→③ | `00b_HostDepletion/` (+`assembly_ready.list`) | `host_depletion.py` → `virome_pipeline.py --input_reads` |
| B3 | ③→④ | `final_centroids.fasta` + `final_integrated_classification.tsv` → 桥转 `reference.fasta/ref_info.tsv` | `discovery2analysis.py --from-discovery` → `auto_known_virus.py --reference --ref_info` |
| B4 | ④→⑤ | `06_Extraction/<病毒>/<样本>.full.fasta` | `extract_full_fasta.py` → `phylo_pipeline.py --extract_dir` |
| B5 | ①→⑤ | `Global_Unified_Metadata_Core14.csv` | `gsa_sra.info.py` → `phylo_pipeline.py --metadata` (原生直读) |
| B6 | ①→⑥ | `all.genome.uniq.fasta` (宿主基因组) | `download_host_genome.py` → `eve_screen.py -g/-B` |
| B7 | ③↔⑥ | 发现输出 → `dna_vs_eve_filter.tsv` (REMOVE/MOVE_EVE/KEEP_virus/REVIEW) | `eve_distinguish/run_all.sh -D <③根>` |

每个边界都有**代码级验证** (本 wiki 09 页记录审计过程); B3 桥支持双布局自动定位
(`--from-discovery <③根>` 即可, 兼容 legacy 三代目录名), 并登记
`90_Handoff/handoff_manifest.tsv` 交接台账。

## 3. 双目录布局 (v3.1)

| | legacy (默认) | standard (管线独立根) |
|---|---|---|
| 定义 | v3.0 现行名 (`00a_CleanData`/`02a_Identification`/`09a_Virome_Analysis`…) | `01_PublicData` `02_Preprocessing` `03_Discovery` `04_Analysis` `05_Phylo` `06_EVE` + `90_Handoff` |
| 根内编号 | 字母后缀体系 | 各管线独立从 01 编号 (⑤ per-virus: 01_data…08_report) |
| 编排器根语义 | ②③ 共享一个输出根 | 每个 `--output_dir` 指向本管线自己的根 |
| 兼容性 | 全部既有 checkpoint 零影响 | 冻结测试保护, 新项目开跑前切换 |

- 解析优先级: `--io-layout` > 环境变量 `MMPV_IO_LAYOUT` > legacy; 编排器入口
  `normalize_layout_env()` 写回环境, 子进程自动继承。
- 唯一注册表: `mmpv_common/io_layout.py` (34 逻辑键 × 2 布局); 改名 = 改一张表 +
  过 `mmpv_common/tests/test_io_layout.py` 冻结测试。
- 边界产物定位器 `locate_centroids()/locate_taxonomy()` 双布局通吃; 桥脚本
  `discovery2analysis.py --from-discovery` 无需开关。
- 完整规范: [doc/IO_LAYOUT_DESIGN.md](https://github.com/zhangwenda0518/MMPV-RNA/blob/main/doc/IO_LAYOUT_DESIGN.md)。

## 4. 横切机制 (全局)

| 机制 | 实现 |
|---|---|
| 断点续传 | 全编排器 `--resume/--force`; `.ok` 标记 + 产物核验双条件; ⑤ 用 `.checkpoints/` + 输入指纹; ⑥ 按阶段产物存在性 |
| 配置 | `pipeline_config.yaml` profile 体系 (default 锚点, plant/downstream 继承); 路径 `${ENV:-default}`; 优先级 CLI > profile > 代码默认 |
| 环境变量 | `MMPV_DB_ROOT` 一变量迁移全部库; 派生 `MMPV_VIRUS_DB`/`MMPV_HOST_DB`/`MMPV_EVE_*`/工具路径 |
| 布局传播 | `MMPV_IO_LAYOUT` 环境变量; 编排器入口 normalize, 子进程继承 |
| 防挂死 | `process_guard.py` (③④ 共用); EVE `--cmd-timeout` |
| 宿主控制 | ② Kraken2 `keep_taxids:10239` 病毒 reads 救回; ③ rescue 前宿主预过滤省 70%+ 计算 |
| 元数据主干 | `Global_Unified_Metadata_Core14.csv` 14 列标准表 (① 产出, ④⑤ 消费) |
| 部署 | `pixi.toml` 100 包; `scripts/db_setup/mmpv_db.py` 管理 50 项数据库 (必需 25) |
| 版本台账 | `SOFTWARE_VERSIONS.txt`; 文档权威体系见各管线 doc.md |
